# 场景定案：电商售后智能客服

> 定案日期：2026-09-01（Day 1）
> 用途：统一业务口径，做知识库内容、golden set、演示分镜时都以本文为准。

## 一、场景一句话

面向电商平台的售后智能客服：客户用自然语言咨询订单、物流、退换货、投诉，系统自动分流、查单、给出处理方案；无法解决或客户要求时转人工并自动建工单。

## 二、意图定义（4 类 + 转人工）

| 意图 | 含义 | 典型处理 |
|---|---|---|
| 订单查询 | 查订单状态、金额、下单时间、商品明细 | 订单 Worker 查模拟订单库 |
| 物流查询 | 查物流轨迹、预计送达、签收情况 | 物流 Worker 查模拟物流库 |
| 退换货 | 退款/退货/换货资格、流程、进度 | 退款 Worker + 规则判断 |
| 投诉 | 服务/商品投诉、要求升级处理 | 自动建工单 → 转人工 |
| 转人工 | 低置信度、Critic 判定、用户主动要求 | 三路汇合转人工 + 建单 |

## 三、种子话术（10 条，golden set 从这里扩展）

1. 我的订单到哪了？
2. 订单 20260901001 什么时候发货？
3. 我买的手机物流显示三天没动了，帮我看看。
4. 这个商品能退吗？我还没拆封。
5. 我要退货，运费谁出？
6. 退款什么时候到账？
7. 你们发的货少了一件，我要投诉。
8. 客服态度太差了，我要找人工。
9. 帮我改一下收货地址，订单还没发货。
10. 这个杯子碎了，申请换货。

## 四、演示主链路（面试讲这条）

客户问「我买的手机物流显示三天没动了，能退吗」：

1. Router 识别为「退换货 + 物流」复合意图
2. Planner 拆解：查订单 → 查物流 → 判断退款资格
3. Workers 并行/串行执行（MCP 工具），返回订单状态、物流轨迹、退款规则
4. Critic 复审：回答是否基于数据、是否答非所问
5. 给出处理方案；若客户要求投诉或超时未解决 → 自动建工单 → Java 状态机流转

## 五、评测指标（如实记录）

| 指标 | 口径 |
|---|---|
| 意图准确率 | Router 分类正确率（目标 ≥90%） |
| 转人工率 | 转人工占比（越低越省人力，但不过低） |
| 误答率 | 答错且未转人工（Critic 引入后对比下降） |
| FCR 代理 | 首轮回答即解决占比（行业基准约 70%） |
| 工单闭环率 | 建单 → 解决/关闭 完成占比 |
| P95 延迟 | 端到端响应（压测如实记录） |

> 面试对标只引用行业公开案例（如转人工率降 45-55%、FCR 行业基准 70%），不冒充本项目数字。

## 六、模拟数据

- 知识库：模拟电商售后制度/规则文档（退款规则、运费规则、投诉流程）
- 订单/物流：内存或 JSON 模拟服务（Day 2 起）
- 不接真实商家系统
